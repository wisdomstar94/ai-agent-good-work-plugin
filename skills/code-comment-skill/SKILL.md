**주석은 최대한 지양합니다.** 꼭 남겨야 한다면 **짧고 명료하게** 씁니다.

코드가 바뀌었을 때 주석도 따라 바뀌지 않으면, **틀린 설명이 그대로 남아** 다음에 코드를 읽는 사람을 잘못된 전제로 끌고 갑니다.
없는 주석은 아무도 오해시키지 않지만, 낡은 주석은 반드시 누군가를 오해시킵니다.

## 코드만 보고 알 수 있는 내용은 주석으로 달지 마세요

예를 들어 `count += 1` 위에 `// count 를 1 증가` 같은 주석을 달지 않습니다. 주석에는 코드에 드러나지 않는 이유나 제약만 남깁니다.

## 로컬 PC 에 종속된 내용을 주석에 포함하지 마세요

로컬 PC 에 종속된 내용(예: 저장소 밖의 파일 또는 gitignore 에 의해 git 에 포함되지 않는 파일 등)을 주석에 적지 마세요.
다른 팀원이 이 주석을 보면 혼란스러울 수 있습니다.
