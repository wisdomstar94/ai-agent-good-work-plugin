지정한 코드 변경 내용을 **리뷰**하고 **HTML 리뷰 결과서**를 만드세요.

사용자가 인자를 넘겼다면 **대상 브랜치 · PR 번호** 또는 **커밋 범위**로 사용하세요 : `$ARGUMENTS`

사용자가 범위를 제한하지 않았으면 **현재 브랜치의 변경사항**을 대상으로 합니다.

---

## 코드 리뷰

- 변경 된 내용을 파악해서 정리합니다.
- 변경으로 인해 사이드이펙트가 **발생할 여지가 있는 곳**과 **발생이 확실한 곳**을 파악하고, 우려되는 점도 전부 나열합니다.
- 변경된 부분 및 그와 연관된 코드에서 주석에 일관성이 있는지 확인합니다. 즉, 낡은 내용의 주석이 있는지 정리합니다.
- 리뷰에서 지적한 내용에 대한 해결책을 같이 제안하세요.

## HTML 리뷰 결과서 작성

- 코드 리뷰 내용은 워크스페이스 루트 경로 기준 `./logs/코드리뷰결과서/YYYYMM/YYYYMMDD/YYYY-MM-DD-HH-mm-ss_무슨무슨_코드리뷰결과서.html` 경로로 html 단일 파일로 생성하세요.
- html 문서 작성 규칙(`../html-writing-skill/SKILL.md`)을 준수하세요.

## 금지 사항

- 리뷰를 하면서 코드를 임의로 수정하지 마세요. 수정이 필요한 부분은 HTML 리뷰 결과서에 포함하여 사용자가 한번에 확인 할 수 있게 하세요.
