## 작업을 시작하기 전 작업계획서를 먼저 작성하고 승인을 받으세요

- 사용자가 작업을 요청하면 **반드시 Markdown 형식으로 작업계획서를 먼저 작성**하고, 워크스페이스 루트 기준 `./logs/작업계획서/YYYYMM/YYYYMMDD/YYYYMMDD_HHmmss_작업설명_작업계획서.md` 경로에 **저장한 뒤 승인(컨펌)**을 받으세요.
- 단, 사용자가 요청한 작업이 매우 간단하거나 작업계획서를 작성하는 것이 오히려 병목이 된다면 사용자에게 작업계획서를 작성하지 않고 바로 진행해도 되는지 질문 프롬프트로 물어보세요.
- 또한 `code-review-skill` · `explain-diff-skill` 처럼 산출물과 진행 절차가 정해진 스킬을 적용하는 작업은 작업계획서 없이 그 스킬의 절차를 따릅니다.
- 계획서를 작성하다 물어볼 것이 생기면 바로 묻지 말고 작업계획서에 담아 두었다가, 계획서를 저장한 뒤 한꺼번에 물어보세요. (작업계획서 생략 여부를 묻는 질문은 예외입니다.)
- 사용자의 결정이 필요한 항목은 작업계획서에 `결정 필요` 라는 섹션으로 한 곳에 몰아 정리하세요.
- 사용자가 답변하면 그 내용에 맞춰 작업계획서를 수정하고, 더 질문할 내용이 없으면 **계획서대로 진행할지 / 추가 요청이 있는지**를 최종적으로 물어보세요.

## 작업계획서를 작성할 때

- 요구사항 구현에 **재사용할 수 있는 공용 컴포넌트 · 함수 등이 있는지 확인**하세요. 기존 공용 코드를 그대로 쓸 수 있거나 약간 커스텀해 쓸 수 있다면 그 내용과 **영향(수정) 범위**까지 계획서에 넣습니다.
- 특정 로직이 여러 곳에서 중복되면 **공용 코드로 관리할 것을 제안**하세요.

### 작업계획서 작성 시 기획 문서 또는 디자인 문서를 참조해야 할 경우

- 기획 문서는 화면정의서와 명세를 말하며, Figma 노드 링크, Google Slides 링크, Google Docs 링크, 이미지 등 여러 종류가 될 수 있습니다.
- 디자인 문서는 Figma 노드 링크, Adobe XD 링크, Zeplin 링크, 이미지 등 여러 종류가 될 수 있습니다.
- 문서 종류에 맞는 MCP 도구나 명령어로 내용을 읽고, 아래 표 규격대로 작업계획서에 내용을 포함합니다.

```text
| No. | UI 요소 (화면정의서)          | UI 요소 (디자인)              | 명세 내용                            | UI 설명              | 구현 계획 |
| --- | ------------------------- | ------------------------- | -------------------------------- | ------------------ | ------- |
| 1   | UI 요소 이미지 (+링크주소) | UI 요소 이미지 (+링크주소) | 명세에 대한 내용 또는 이미지 (+링크주소) | 해당 UI 에 대한 설명 | 수정 위치, 기존 코드 재사용 또는 신규 작성 여부, 명세에 적힌 OO 기능의 구현 방식 등 화면정의서 · 디자인 · 명세에 대한 구현 계획 |
| 2   | ...                       | ...                       | ...                              | ...                | ... |
```

- 화면정의서 · 디자인 · 명세 중 참조할 자료가 없는 항목의 열은 생략합니다.
- `UI 설명` 열은 화면정의서와 디자인이 모두 없으면 생략합니다.

### 수정 이력

작업계획서가 최초 작성된 뒤 내용이 바뀌면 `수정 이력` 섹션에 남깁니다.

- 형식 : `- YYYY-MM-DD HH:mm:ss : ...`
- 일시 기준 **오름차순**으로 정렬해, 가장 나중에 추가된 이력이 제일 아래에 오게 합니다.

## 작업 중 계획을 바꿔야 할 때

- 작업 중 예상치 못한 이슈로 계획을 바꿔야 하면, **먼저 질문 프롬프트로 여러 선택지를 제시하며 물어봅니다.**

## 작업 완료 후

- 작업이 끝나면 바로 코드 검증을 진행하세요. (타입 에러 체크, 린트 에러 체크, 빌드 에러 체크 등)
- 완료 보고는 기존 작업계획서의 맨 아래에 `작업 완료 보고` 섹션을 추가하세요. 별도 md 파일을 생성하지 않습니다.
- 작업계획서 작성을 생략한 경우에는 완료 보고를 터미널(채팅)에 합니다.
