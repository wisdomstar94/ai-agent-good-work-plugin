어떠한 작업이더라도 해당 스킬을 준수해야 합니다.

## 작업을 시작하기 전 작업계획서를 먼저 작성하고 컨펌을 받으세요

- 사용자가 작업을 요청하면 **반드시 md 문법으로 작업계획서를 먼저 작성**하고, 워크스페이스 루트 기준 `./logs/작업계획서/YYYYMM/YYYYMMDD/YYYYMMDD_HHmmss_작업설명_작업계획서.md` 경로로 **저장한 뒤 컨펌**을 받으세요.
- 단, 사용자가 요청한 작업이 매우 간단하거나 작업계획서를 작성하는 것이 오히려 병목이 된다면 사용자에게 작업계획서를 작성하지 않고 바로 진행해도 되는지 질문 프롬프트로 물어보세요.
- 계획서를 작성하면서 물어볼 것이 있으면, 해당 질문을 작업계획서에 포함하여 작업계획서를 먼저 작성한 뒤에 한꺼번에 물어보세요. 작업계획서를 작성하기 전에 먼저 물어보지 마세요.
- 사용자의 결정이나 답변이 필요하여 질문이 필요한 항목들은 작업계획서에 `결정 필요` 라는 섹션으로 한 곳에 몰아 정리하세요.
- 사용자가 답변을 하면 답변 내용에 맞춰 작업계획서 내용을 수정 후 더 이상 질문할 내용이 없으면 **계획서대로 진행할지 / 추가 요청이 있는지**를 최종적으로 물어보세요.

## 작업계획서를 작성할 때

- 계획서를 쓸 때 요구사항을 구현하기 위해 필요한 부분들에 대해 **재사용 가능한 공용 컴포넌트·함수 등이 있는지 확인**하세요. 기존 공용 코드를 그대로 쓸 수 있거나 약간 커스텀해 쓸 수 있다면 그 내용과 **영향(수정) 범위**까지 계획서에 넣습니다.
- 특정 로직이 여러 곳에서 중복되면 **공용 코드로 관리할 것을 제안**하세요.
- 작업 중 예상치 못한 이슈로 계획을 바꿔야 하면, **먼저 질문 프롬프트로 여러 선택지를 제시하며 물어봅니다.**

### 작업계획서 작성 시 기획 문서 또는 디자인 문서를 참조해야 할 경우

- 기획 문서는 피그마 노드 링크, 구글 프레젠테이션 링크, 구글 Docs 링크, 이미지 등 여러 종류가 될 수 있으며 종류에 맞춰서 적절한 MCP 도구나 명령어로 기획 문서 내용을 읽고 작업계획서를 작성해야 합니다.
- 디자인 문서는 피그마 노드 링크, Adobe XD 링크, 제플린 링크, 이미지 등 여러 종류가 될 수 있으며 종류에 맞춰서 적절한 MCP 도구나 명령어로 디자인 문서 내용을 읽고 작업계획서를 작성해야 합니다.
- 기획 또는 디자인 문서를 읽고 아래 표 규격대로 작업계획서에 내용을 포함합니다.

```text
| No. | UI요소 (화면정의서) // 없으면 생략 | UI요소 (디자인) // 없으면 생략 | 명세 내용 // 명세가 없으면 생략        | UI 설명 // 화면정의 또는 디자인이 없으면 생략 | 구현 계획 |
| --- | --------------------------- | ------------------------- | ------------------------------- | ----------------------------------- | ------- |
| 1   | UI요소 이미지 (+링크주소)        | UI요소 이미지 (+링크주소)      | 명세에 대한 내용 또는 이미지 (+링크주소) | 해당 UI에 대한 설명                      | 어디를 수정할 건지, 기존 코드를 재사용할 건지 새로 만들 건지, 명세에 적힌 ~~기능은 어떤 식으로 구현할 건지.. 등등 화면정의 or 디자인 or 명세에 대한 구현 계획 작성 |
| 2   | ...                         | ...                       | ...                             | ...                                  | ... |
```

## 수정 이력

작업계획서가 최초 작성된 뒤 내용이 바뀌면 `수정 이력` 섹션에 남깁니다.

- 형식 : `- YYYY-MM-DD HH:mm:ss : ...`
- **가장 나중에 추가된 이력이 제일 아래**에 오도록 정렬합니다. (수정 이력의 날짜를 기준으로 오름차순 정렬)

## 작업 완료 후

- 작업이 끝나면 바로 코드 검증을 진행하세요. (타입에러체크, 린트에러체크, 빌드에러체크 등)
- 완료 보고는 기존 작업계획서의 맨 아래에 `작업 완료 보고` 섹션을 추가하세요. 별도 md 파일을 생성하지 않습니다.
